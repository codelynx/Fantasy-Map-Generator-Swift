**What the upstream tests tell us to check** (they run on a square outline from 10 to 90 on a 100×100 map): the same seed and settings repeat the same coast, whatever else was generated before; a different map seed gives a different coast; a new `variant` reshuffles and returning to the old variant returns the old coast; moving one vertex changes only the stretch around it (under a quarter of the path's commands, on a 24-vertex ring); a smaller `maxDepth` gives a shorter path; `enabled: false` gives the plain outline.

## What the original does (in the review's reading order)

1. **Seed and integer noise.** A feature's seed is `Alea("<mapSeed>_c<featureId>_<variant>").uint32() | 0`: one `next()` call times 2³², then JavaScript's `|0` truncation to a 32-bit integer. `noise(seed, ...ints)` is murmur-style mixing in 32-bit integer arithmetic (`Math.imul` by `0x5bd1e995`, `^= h >>> 13`, then the `0x85ebca6b` / `0xc2b2ae35` finaliser) giving a value in [0, 1). It is **keyed by integers, not by sequence**, which is why an edit leaves distant coast alone. The Swift side already has the 32-bit conversions in `JSNumber`.
2. **Roughness field.** `roughnessAt(seed, x, y)`: two octaves of smoothstep value noise on a lattice of `roughnessScale` map units (60) and half that (seed XOR `0x9e3779b9`), blended 65/35, stretched by 1.9 around ½, clamped to [0, 1] and raised to `roughnessContrast` (1.5). Uses `Math.floor`, floating point and `**` (a power function: a place where Swift's result could differ from V8's in the last bit).
3. **Subdivision.** For each polygon edge a→b, recursively (depth 4): stop if depth is 0, the edge is shorter than `minEdge` (1) or the amplitude is 0; look up the roughness at the midpoint and **stop if it is below `smoothThreshold` (0.25)**; otherwise displace the midpoint **perpendicular** to the edge by `(noise(seed, quantised ends, depth) − ½) × √length × amplitude × roughness`, with the ends quantised by `Math.round(value × 64)` (**JavaScript rounds halves up, not away from zero; Swift's `rounded()` differs for negative halves**), and recurse on both halves with the amplitude times 0.9. Lakes use a calmer threshold (the threshold times 2, capped at 1).
4. **Frame edges.** Edges **with both ends on the map border are skipped.** Displaced points are not clamped: the original relies on the SVG viewport and on the outline having been clipped to the map first.
5. **Path construction.** The displaced polygon becomes an SVG path: spans that were never subdivided are a quadratic B-spline through midpoints, subdivided spans a Catmull-Rom curve (tension ⅛ of the neighbour difference) through every sub-point. This is curve drawing on top of the displacement, **not part of the kernel**.
6. **Simplification and clipping.** The outline fed in is the feature's packed-graph vertices, simplified with `simplify.js` (tolerance 0.3) and clipped to the map. **These serve a different source outline** from ours, which comes from grid cells and is already smoothed.

## Proposed decisions (to be confirmed)

- **Port the displacement kernel only:** `noise`, the two-octave `roughnessAt`, the recursive subdivision with the original's rules and constants, and the JavaScript rounding and integer conversions. **Do not port** `simplify.js`, `clipPoly` or the SVG curve construction; **do not import tolerance 0.3.** The result is a polyline of displaced points (dense enough at depth 4 that a Catmull-Rom flattening can be added later if wanted).
- **Parity target:** the kernel against the original on **explicit outlines, seeds and settings** (fixtures from the original's own code, the same capture method as the rest of the package: bundle, stub the globals `options` and `Options`, run in Node, record provenance). Whole-map parity is not a target, as the design says. Expect exact structure and points equal to a tight tolerance; the `**` power and rounding are where a difference could show, and any difference is recorded, not tuned away.
- **Two paths, so an open coast is never closed by accident.** The original's `fractalize` treats its input as **closed, last point back to first**. This package needs both: a **closed-loop path** (islands and lakes: the original's behaviour, including the last-to-first edge) and a separate **open-chain path** (a coast running from frame to frame) that subdivides **only consecutive segments**, **preserves both end points** (it only inserts midpoints) and never adds a last-to-first edge. An edge with both ends on the frame is skipped, as in the original.
- **Where it sits:** smoothing first, **then roughening**, applied to the coast pieces and the closed loops **before frame closure** and before the fill rings and the ink are taken, so both stay one boundary.
- **Seeding is this package's integration policy**, separate from the original's `featureSeed` (which the fixtures test as it is). One seed from the map's seed and the `variant` is used for the whole map. The noise is keyed by position, so this avoids changes when features renumber; it does **not** promise that a stretch of coast stays the same when the endpoints or orientation of its segment change.
- **Displacement bound, stated carefully.** Capping each midpoint's own offset **does not** cap the total distance from the input boundary, because the recursion accumulates, and adjacent cells can be much narrower than the nominal spacing. So **no claim that colour support "holds by construction"** is made. The bound used is on the **total** distance of every output point from the smoothed input line, starting at **0.1 of the grid spacing** for the first visual trial; it is a trial value and not a correctness guarantee. Correctness comes from **validation**: after roughening, the colour support of the changed strip is checked (sample points between the smoothed and the roughened boundary must fall in cells the 2b borrowing covers, that is, cells that touch the other kind) and, if it fails, the drawing falls back. The alternative, extending the colour support to the displaced boundary, stays open.
- **Clamping and the frame.** A displaced point is clamped into the rectangle. Clamping can collapse points or create overlapping segments along the frame, so the checks after roughening include: no consecutive duplicate points, no ink segment along the frame, no crossings (as in 2b) and a consistent frame closure.
- **Fallback:** if any check fails (closure, crossings, frame segments, colour support), **the whole drawing uses the validated 2b smoothed boundary** and a flag on the outlines says so. **Settings are never reduced silently until something passes.** Per-ring fallback is possible later.
- **Lakes calmer:** a closed loop with negative area (water enclosed by land) takes the lake threshold multiplier. This orientation rule is this package's first convention for enclosed water and is kept distinct from the original's feature classification.
- **Settings and limits.** An optional value in the style (`nil` = off, the default) holding the original's knobs with **the original's absolute map-unit defaults** (depth 4, amplitude 1.5, decay 0.9, minimum edge 1, calm threshold 0.25, contrast 1.5, scale 60, lake multiplier 2, variant 0). **Grid spacing is used only as a safety cap (above), described separately from amplitude and scale;** a density-relative mode is considered only after appearances at different densities have been compared. Before any setting is exposed: **every parameter must be finite and in a stated range, the recursion depth bounded (a maximum to be set at step 3, with 4 the default), and the number of output points budgeted** (estimated before work starts: each segment can become up to 2^depth pieces); settings outside the limits are refused, not clamped.

## Build order, each step tested before the next

1. **Fixtures from the original** *(done 2026-10-20; [step page](../steps/drawing-2c-1-fixtures.md))*, exact point comparison first: `noise` values for sets of integers and seeds, `roughnessAt` on a grid of points, `featureSeed` for several strings, and `fractalize` on explicit closed outlines (a square, an irregular polygon, one with edges on the border) with several seeds and settings. **`enabled: false` is handled by `getFeatureShape`, not by `fractalize`,** so the fixtures capture that layer for the bypass; the raw kernel is not expected to honour the flag. The harness stubs the globals as the upstream test does (`options.map.seed` and `graph`, `options.map.coastline`, `pack.vertices`, an identity `simplify`). **If `**` produces a mismatch, it is captured and investigated before any tolerance is introduced and documented.**
2. **Port the kernel** *(closed-loop path done 2026-10-20; [step page](../steps/drawing-2c-2-kernel.md); the open-chain path is still to do)* (closed-loop path) with those fixtures as tests, plus the arithmetic edge cases (negative halves in the rounding, 32-bit overflow in the mixing, seeds beyond 2³¹) and the upstream behaviours listed above (repeatability, variant, local edit). Then the **open-chain path**, tested for preserved end points, no closing edge and consecutive-segment-only subdivision.
3. **Integrate** *(done 2026-10-20; [step page](../steps/drawing-2c-3-integration.md))* after smoothing, with the total-displacement bound, the clamp, the lake rule, the validation checks, the fallback flag, and the parameter validation and output budget.
4. **Tests:** crossings and frame closure at several settings and variants; strict land/water colour and changed-strip checks as in 2b (the colour-support validation is exercised, including a deliberately over-large amplitude that must fall back); open ends on the frame; same inputs give the same line; off gives exactly the 2b result.
5. **Pictures by eye,** at default settings and at stronger ones, kept as examples.

## What this plan does not claim

The kernel reading is from the source, not from running it. The displacement bound, the clamp, the open-chain path, the lake rule and the single seed are choices of this package that the original does not make; the bound is a trial value, not a guarantee. A smooth, hand-drawn look is a judgement made by eye after step 5, not a promised result.
