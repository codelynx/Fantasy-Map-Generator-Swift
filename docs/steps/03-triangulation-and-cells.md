# Step 3: The Triangulation and the Voronoi Cells

Built 2026-10-20, as step 3 of [the land plan](../plans/land-layer.md).

## What it does

- **`RobustPredicates.orient2d`** (`Geometry/RobustPredicates.swift`): a port of `orient2d` and the expansion helpers it needs from `robust-predicates` 3.0.3 (about 320 lines in the original; its other predicates are not used by Delaunator and are not ported). Every expression is evaluated in the original's order, with no reassociation and no fused multiply-add, so the sign and the value are the same, including on the adaptive (exact) path for nearly collinear points. JavaScript reads past the end of a typed array as `undefined`; the helper reads those as 0 where the value is never used.
- **`Delaunay`** (`Geometry/Delaunay.swift`): a port of `delaunator` 5.1.0. Its `triangles`, `halfedges` and `hull` come out in the original's order, which decides the cells' neighbour order and so later stages. Duplicate points are skipped; collinear points give an ordered hull and no triangles; zero, one or two points follow the original too. Two JavaScript behaviours are handled deliberately:
  - **A hash key that is not a finite number** (a point exactly at the seed triangle's circumcenter makes the angle 0 / 0). The original then indexes a typed array with NaN and `undefined` propagates through later steps in ways a sentinel cannot reproduce, so this port **reports `unsupportedDegenerateInput` instead of guessing**. So does an exhausted hash probe: the probe loop ends with `start == -1` only when the last probe found an empty slot, and the original would then read `hullPrev[-1]`; this port throws. **This is a guarded path whose reachability for supported finite inputs is unknown; no parity with the original is claimed for it.** A search of 3,000,000 random small integer point sets (`tools/searches/find-hash-nan.mjs`) found no input that reaches it (such a point would have been chosen as the seed's third point); it is tested through the function that decides it, and the exhausted-probe throw is not triggered by any test.
  - **The 512-entry edge stack,** which silently stops pushing on extremely degenerate input, is an upstream limitation preserved on purpose, not a guarantee about extreme degeneracy.
- **`VoronoiDiagram`** (`Geometry/VoronoiDiagram.swift`): a port of `voronoi.ts` and `calculateVoronoi`. The boundary points are appended after the cell points, the whole set is triangulated, and only the cell points get cells: for each its Voronoi vertices (triangle indices), its neighbouring cells (boundary points left out) in the original's order, and a border flag; for each triangle its circumcenter, its three adjacent vertices (-1 on the hull, because the original's `Math.floor(-1 / 3)` is -1, not 0 as integer division gives) and the three points that meet there.
- **The public input boundary (added after review).** Both `Delaunay` initialisers throw instead of trapping: a non-finite coordinate (`nonFiniteCoordinate`), a coordinate above `Delaunay.maximumCoordinate` (**1e9, a map up to a billion units across**; `coordinateTooLarge`), an odd number of flat coordinates (`oddCoordinateCount`), and more than `Delaunay.maximumPoints` points (`tooManyPoints`).
- **The numeric range is a supported range with headroom, not a finiteness guarantee (corrected after review).** At 1e9 the in-circle test's fourth-degree products are about 1e36, far below the largest Double; but the circumcenter formulas divide by a determinant that is tiny for nearly collinear points, so a derived coordinate can still overflow however small the inputs are. Such cases are **detected and reported, never returned**: the seed triangle's circumcenter not finite throws `DelaunayError.nonFiniteGeometry`, and a Voronoi vertex that is not finite throws `VoronoiDiagramError.nonFiniteGeometry`. Ordinary inputs are not rescaled, so parity is unchanged. A search (`tools/searches/find-nonfinite-circumcenter.mjs`) found five nearly collinear points near 1.9e8 for which the original's own formula gives a non-finite circumcenter; that input is a regression test, and the triangulation of it matches the original's.
- **Scale and degeneracy tests:** scaling every coordinate of the three fixture grids by a power of two is exact in floating point, so the large-scale configuration must give the same triangles, half-edges, hull, cells and (scaled) vertex coordinates as the ordinary-scale one, with no normalisation; it does. The nearly collinear case above is the near-collinear test.
- **Map containment is not enforced here.** The geometry layer enforces its numeric and structural input contract; whether points lie inside a map is the grid stage's and the saved-map validation's job (boundary pseudo-points are outside the map on purpose).
- **Budget (the review of step 2 asked for it here):** `VoronoiDiagram.maximumInputPoints` (the same 400,000 as `Delaunay.maximumPoints`) bounds the **combined** cell and boundary points given to the triangulation, which sizes about twenty working arrays, and is checked before anything is allocated. It is provisional and not a performance claim. Input that does not triangulate throws `degenerate`.

## How it is tested (against the original's own output)

- **`orient2d`:** compared exactly (value and sign) with `robust-predicates` 3.0.3 on: 167 nearly collinear cases; **30 cases chosen to reach each of the five return points** (the fast filter, the first exact estimate, all-zero tails, the first correction, and the full exact sum), found by running an instrumented copy of the library's own source (built in a temporary folder, with every value checked against the real library) and **asserted to reach the same branch in the port**; every permutation of one case per branch (odd permutations flip the sign); and five exactly collinear triples in every order (always zero). **The sign convention is pinned:** the original gives -1 for (0,0), (1,0), (0,1), and a globally reversed port would fail. The cases come from a search I wrote (the procedure is in `tools/capture-fixtures.mjs`), not from the library's own test suite, which I did not read; adding the upstream cases would be worthwhile. **This is return-branch coverage, not exhaustive numerical coverage** of the expansion arithmetic.
- **`Delaunay`:** `triangles`, `halfedges` and `hull` of the three tiny grids compared with Delaunator 5.1.0's, in order.
- **Voronoi cells against the original's own `Grid.generate`:** for **all eight** captured grids (including the original's default 1280 × 800 map with 9,954 cells, the two accent spellings and the two odd aspect ratios), a SHA-256 of the integer structure of every cell and vertex (neighbours, vertices, border flags, vertex adjacency, vertex cells) matches, the vertex count matches, **and a second SHA-256 over every vertex's coordinates (the little-endian IEEE-754 bytes of x then y, in order, shared by Node and Swift) matches exactly, with every coordinate checked finite**; for the five small grids the full ordered neighbours, cell vertices, border flags and all vertex points are compared field by field. All match.
- **Properties:** twins are mutual, neighbours are mutual, cells have at least three vertices, a hull vertex is -1, degenerate and tiny inputs follow the original, the budget refuses an oversize input.
- **Optimised build:** the same 42 tests pass in a release build.

## A measurement, not a promise

On the machine this was built on (one run each, not a benchmark): the 10,000-cell default map's cells took 8 ms in a release build (84 ms debug); a **100,000-cell map** took 86 ms in release (890 ms debug), plus 3 ms (11 ms) for the points. This is evidence that the default size and the largest density step are not slow here, not a guarantee for other devices.

## What it does not show

The triangulation and cells match the original (full integer structure and every vertex coordinate) for these eight grids, and `orient2d` matches on the cases above, at the dependency versions in `Fixtures/original/provenance.json`; that is not a proof for every input. **Peak memory and elapsed time at the 400,000-point ceiling were not measured**; the timings above are for 10,000 and 100,000 cells only, and nothing is promised for the upper range. Degenerate point sets beyond the simple cases tested (many near-duplicates, an exact circumcenter hit) are handled as the original does by reading, not by comparison.
