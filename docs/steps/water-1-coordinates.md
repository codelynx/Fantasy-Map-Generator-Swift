# Water chain, stage 1: coordinates (where the map sits on the globe)

Status: built 2026-10-20; review correction applied (extreme aspect ratios, a validating public `calculate`) (plan: [water.md](../plans/water.md)). First stage of the faithful port of the original's water chain.

## What was built

- **`Geography`** (`Sources/FantasyMapKit/Climate/Geography.swift`), a port of `Coordinates.generate` and its `calculate` from `coordinates.ts` at the pinned original (commit `8936c9c`), with the helpers it uses: `P` (a probability that draws nothing at 1 or more and at 0 or less), `gauss` (d3-random 3.0.1's `randomNormal`, Marsaglia's polar method, a fresh generator per call, then clamped and rounded with JavaScript's rounding), `rn` and `minmax`. The tables of real-world positions, the whole-world chances and the random size distributions are the original's.
- **`GeographyRequest`:** the author's mapSize, latitude shift and longitude shift (percentages), each used when given and drawn from the template otherwise; **the original draws for the template even when every value is requested, and so does the port** (the stream moves the same way), and 0 counts as a value.
- **The random stream:** `Geography.generate(for: map)` starts from **a fresh `Alea(seed)`**. This is not an assumption: the capture shows that for every seed the stream's state before the original's `Coordinates.generate` is the state of a fresh `Alea(seed)` (`Features.markupGrid` resets it to the seed and the two lake steps after it draw nothing), and the Swift test checks the same for all 123 runs. So the result does not depend on what the height generator left behind, and it is the same from a loaded `LandMap` (which stores no random state). The template is the map's recipe template (an empty string if there is none: **a missing template is the generic size distribution, not a recovery of the map's original template**); "partial" is derived from the map's features (land touching the border). The resolved geography should be kept with the climate state, so that a later load need not infer it from the recipe.
- The explicit form `generate(template:isPartial:width:height:request:random:)` takes the caller's stream, for callers that manage their own.
- **Safety refusals, documented as divergences from the original:** a requested value that is not finite or outside 0 to 100, a map width or height that is not finite and above 0, and an **aspect ratio whose width / height overflows** (with a map size of 0 the longitude span would be infinity × 0 = NaN) are refused with named errors (`invalidRequest`, `invalidSize`, `unsupportedAspectRatio`) before any draw; the original takes the values as given. **The public `calculate` validates in the same way** (it throws) and checks that its result is finite; the unchecked arithmetic is private and keeps the original's order. The stream is advanced on a local copy committed only on success: with the preflight no input reaches that point today, so it is defence in depth and has no test of its own. A zero-span geography (map size 0) is accepted because the original accepts it; **temperature and rain must separately handle or refuse it.**

## Fixtures and tests

`tools/capture-original-coordinates.mjs` (wired into `tools/capture-original.sh`, with `d3-random`'s version added to `provenance.json`) runs the original's own `Grid.generate`, `HeightmapGenerator.generate`, `Features.markupGrid`, `Grid.addDeepDepressionLakes`, `Grid.openNearSeaLakes` and then `Coordinates.generate`, and records for 123 runs the stream's state before and after, whether the map is partial, the geography chosen and the box calculated: every one of the fourteen templates on six map configurations (1,280 × 800 down to 100 × 60, including an empty seed, a non-ASCII seed and a very wide map), five of the real-world positions (`europe`, `world`, `iceland`, `us-centric`, `world-from-pacific`) on three configurations, and 24 runs with requested values (some, all, a zero). The fixtures check (capture twice, identical; the six earlier fixtures unchanged).

`GeographyTests` (11): **all 123 runs equal the original exactly** (the geography, the latitude and longitude bounds, **the stream's state before and after, so the number of draws is checked**); the fixtures observe exact final values and do not separately compare each intermediate logarithm; **the whole loop on 84 generated maps** (our own heights, features and recipe against the original's chain: the partial flag and the geography agree on every one); a loaded map gives the same geography; `P` at the edges draws nothing and inside draws one; `gauss` stays in its bounds and rounds; the box on hand-computed cases; requests used when given and still costing the draws; refusals draw nothing; **extreme aspect ratios** (width 1e300 over height 1e-300 refused at map sizes 0, 50 and 100, in `generate` and in `calculate`, with the stream untouched; the largest ratios that are still finite give finite results, a ratio that underflows to 0 gives a zero longitude span, a huge finite ratio is limited to 360); the public `calculate` refuses what `generate` refuses; a successful call advances the stream by exactly the template's draws. **Mutation checks** (each made and undone): the whole-world branch skipped, partial maps using a size limit of 100, the atoll rounding dropped, `P` drawing at its edges, the box rounded to whole degrees, the longitude span unlimited, the latitude base reversed, a requested 0 treated as not given, and `gauss` drawing one value per pair: all nine fail.

## Limits and notes

- The fixtures cover the 14 templates, six configurations and a handful of real-world keys; they are a sample. Exact equality of the final values on all of them is observed, not guaranteed for every input; the review judged the cell count irrelevant here (the remaining boundary is the numeric aspect ratio, now covered).
- `d3-random` is now a ported dependency: its ISC notice is in `ACKNOWLEDGEMENTS.md` and `docs/dependencies.md`.
- The next stage, temperature, reads the latitude bounds this produces.
