# Step 6: Features and the Distance Field

Built 2026-10-20, as step 6 of [the land plan](../plans/land-layer.md). Step 7 (the lakes that change heights and coasts) follows it, as in the original.

## What it does

`LandFeatures.markup(heights:voronoi:)` (`Sources/FantasyMapCore/Land/LandFeatures.swift`) ports the part of the original's `features-generator.ts` that `markupGrid` and `markup` implement:

- **Features.** A flood fill numbers every connected body of cells, from 1: **land** (a height of at least 20, `Heights.seaLevel`) is an `island`; **water** that touches the map's edge (a cell the Voronoi step flagged as a border cell) is an `ocean`; water that does not is a `lake`. The fill takes cells last-in-first-out, as the original's `queue.pop()` does, and starts each feature from the first cell no feature has reached. **Finding that cell uses a cursor that only moves forward**: marks only ever increase, so it finds the same cell the original's search from zero finds without rescanning the marked prefix after every feature (which could be quadratic on a very fragmented map). The numbering is unchanged, and a test checks on a fragmented map that features are numbered in the order of their first cells. This is a design argument plus that test, not a benchmark; no large-map timing has been made. Each feature records whether it is land and whether it touches the edge.
- **The distance field.** For each cell, a **graph distance** (steps between neighbouring cells), not a distance in map units: a land cell next to water is 1, a water cell next to land is -1, and water farther out is -2, -3, ... down to -9, found by growing outward one step at a time from the water coast. Land inland, water more than nine steps out, and any cell the growth did not reach stay 0. **This is what `markupGrid` computes: it measures no distance inland, and it does not add a separate full land-distance calculation.** A reader who wants distance inland would have to add that.
- **Not ported here:** names, subtypes (continent, sea, gulf, freshwater and so on), areas, vertices, shorelines and heights of a feature, which later layers of the original compute; and the lakes that change heights, which are step 7. The original resets its random generator at the start of this step to reproduce a map after a height edit, but it draws nothing, so nothing is reset here.
- **Input checks:** the heights must match the diagram's cells, there must be at least one cell, and every neighbour index must be a cell (`inconsistentInput`). More than 65,535 features is refused (`tooManyFeatures`), because the original numbers them in a 16-bit array and would wrap: feature numbers 1 through 65,535 fit, zero stays the "not yet reached" marker, and the check comes before feature 65,536 is assigned. The package's cell ceiling does not itself guarantee fewer features. A targeted test with an injectable small limit shows exactly the limit succeeds with the same result and one below throws; the port refuses where the original would wrap, so the original's wrapping is not reproduced.

## How it is tested (against the original's own `markupGrid`)

`tools/capture-original-features.mjs` runs the original's own `Features.markupGrid()` on heightmaps made by the original's own `HeightmapGenerator.generate`, and saves the feature list, a SHA-256 of the distance field (as signed bytes), a SHA-256 of the feature ids (each written **explicitly little-endian** with `writeUInt16LE`, not through the machine's own byte order), the counts and the set of distance values that occur. For a few maps the complete arrays are saved as well. The wrapper bundles the features module with the others and checks four fixtures.

**All fourteen templates on five grids (70 maps)** are compared: the default 1280 × 800 map of 10,000 cells, 1,000 cells with the empty seed, 2,000 cells with a non-ASCII seed, a 1000 × 90 map of 300 cells, and a 100 × 60 map of 24 cells. For each, the Swift heights are first shown equal to the original's (by their digest), and then the feature list, the digests of the distance field and the feature ids, the feature count and the distance values all match; and cell for cell on the maps with full arrays (the default map's `highIsland` and `archipelago`, the 2,000-cell `shattered`, the 300-cell `lowIsland`, and all fourteen on the 24-cell grid). **The fixtures contain all three kinds of feature (island, ocean, lake) and distance values from -9 to 1.** The same tests pass in a release build, and the wrapper's `--check` finds the four fixtures identical on recapture.

**Small hand-made cases:** all land is one island touching the edge with no coast; all water is one ocean and the field is all 0 (there is no land to grow from); one interior water cell among land is a lake with water coast -1 and land coast 1 around it; water distance grows outward from a straight shore to -9 and never reaches -10; and inconsistent input is refused.

## What it does not show

Parity with the original's features and distance field for these 70 maps at the dependency versions in `Fixtures/original/provenance.json`; not for every map. The lakes that change the heights (step 7), saving and loading, and everything above the land layer are not built.
